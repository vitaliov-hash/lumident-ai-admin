# Техническое задание LumiDent

## Цель

Создать красивый адаптивный веб-сайт-прототип AI-администратора стоматологической клиники «LumiDent». Пользователь должен иметь возможность вести диалог с AI-администратором, получать информацию о клинике и оставлять заявку на запись.

## Рекомендуемый стек

- Frontend: React или Next.js.
- Backend: Next.js API routes, Node.js или отдельный Express-сервер.
- Стилизация: Tailwind CSS либо CSS Modules.
- Хранение заявок для прототипа: локальное состояние или SQLite.
- LLM: DeepSeek API через совместимый OpenAI API-интерфейс.
- LLM вызывается только на backend.

## Визуальный стиль и структура

- Нежные сиреневые, лавандовые и светло-фиолетовые оттенки.
- Белые и молочные поверхности, мягкие градиенты, скруглённые карточки, лёгкие тени, современная типографика, хорошая контрастность.
- Адаптивность для телефона, планшета и компьютера.
- Визуальный элемент зуба или нескольких зубов: иллюстрация в hero-блоке, логотип с силуэтом зуба, иконки зубов в карточках услуг.
- Страница включает верхнюю панель, hero-блок, информационные карточки, популярные услуги, чат, блок «Как записаться» и нижнюю часть с контактами и дисклеймером.

## Логика чата

Frontend отправляет сообщения на `POST /api/chat` в формате:

```json
{
  "messages": [{"role": "user", "content": "Сколько стоит лечение кариеса?"}],
  "sessionId": "demo-session"
}
```

Backend получает историю, добавляет системный промт, отправляет запрос к LLM и возвращает frontend текст ответа и безопасные метаданные.

## Обработка ошибок

Предусмотреть таймаут LLM, пустой ответ, ошибку авторизации API, временную ошибку внешнего сервиса, отсутствие или некорректное содержимое сообщения. Пользователю не показывать stack trace, внутренние URL, API-ключи, служебные заголовки и технические детали исключений.

## Безопасность ключей

- LLM-вызовы выполнять только на backend.
- Не хранить ключ во frontend, не передавать его в браузер, Git или API-ответы.
- Не выводить ключ в логи, скриншоты или документацию.
- Создать `.env.example` и исключить `.env` и `.env.*` из Git, оставив исключение для `.env.example`.
- Поддержать `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`; при отсутствии `LLM_API_KEY` использовать `DEEPSEEK_API_KEY`.

## Ограничения по данным

Не использовать реальные персональные данные пациентов. Демо-заявки должны быть тестовыми и сопровождаться предупреждением о демонстрационном характере прототипа.

## Тестирование агента

Проверить пять сценариев: стоимость лечения кариеса; материалы и гарантия на пломбы; вопрос не по теме; вопрос без ответа о парковке; провокационный вопрос о суперклее. Агент должен отвечать по системному промту, не выдумывать сведения, не одобрять опасное самолечение и предлагать телефон клиники при необходимости.

## Критерии готовности

- Сайт запускается локально по инструкции.
- Интерфейс адаптирован под мобильные устройства.
- Реализованы сиреневая стилистика и визуальный элемент зуба.
- Чат работает через backend.
- Секретный ключ не попадает во frontend.
- Созданы `.env.example` и `.gitignore`.
- Предусмотрены ошибки API.
- Системный промт подключён на backend.
- Все пять тестов пройдены и сделаны скриншоты диалогов.
- Подготовлена ссылка на проект, код или архив.

## Передача после разработки

Подготовить ссылку или архив проекта, инструкцию запуска, объяснение размещения `DEEPSEEK_API_KEY`, скриншоты пяти тестов, список переменных окружения и подтверждение, что ключи не попадают во frontend, логи и ответы API.
