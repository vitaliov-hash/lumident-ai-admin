# LumiDent — AI-администратор стоматологии

## Этап LumiDent Pro (опубликован на Render)

Публичная версия Pro: регистрация и вход, серверные сессии в PostgreSQL, роли клиента и администратора, редактируемые услуги/цены/часы, личная история диалогов. На Render постоянная Neon PostgreSQL подключена через Secret File `DATABASE_URL`. Локально Pro включается при наличии переменной окружения `DATABASE_URL`; без неё запускается прежний прототип ниже. Не размещайте и не используйте приложение для реальных данных пациентов до правовой проверки.

Для Pro требуется постоянная PostgreSQL-база. Создайте её отдельно и задайте `DATABASE_URL` в закрытых переменных окружения Render либо сохраните строку одним секретным файлом с именем `DATABASE_URL` (Render подключает такие файлы в `/etc/secrets`). Не публикуйте строку в GitHub. При запуске сервер создаёт таблицы и один раз загружает исходные услуги и часы работы. Если подключение к БД не удалось, Pro не запускается. Ключ DeepSeek остаётся только в `DEEPSEEK_API_KEY` на сервере. Адрес, телефон и данные клиники пока вымышленные.

Публичная регистрация создаёт только клиента. Для назначения первого администратора зарегистрируйте аккаунт, затем в доверенной среде, имеющей доступ к той же БД, задайте `ADMIN_EMAIL` с адресом этого аккаунта и запустите `npm run admin:promote`. В Render Shell скрипт читает строку из Secret File автоматически. Эту команду нельзя предоставлять посетителям сайта.

Сессии действуют 30 дней и отзываются при выходе. Клиент может удалить свой диалог; неактивные диалоги удаляются через 30 дней при запуске и затем ежедневно. Это техническая политика прототипа, не заменяющая правовую проверку хранения медицинских данных. До такой проверки не вводите реальные сведения о пациентах. Настоящая запись и доставка заявки сотруднику пока не подключены: Pro не обещает подтверждённый визит.

Render Free не подходит как единственное постоянное хранилище: файловая система веб-сервиса эфемерна, а бесплатный Render Postgres истекает через 30 дней. Для долговременной работы нужна подходящая постоянная PostgreSQL-база и решение по резервному копированию. Голос и мультиязычность отложены.

Локальная проверка без внешней БД ограничена проверкой синтаксиса и старого прототипа. Перед публикацией Pro нужно проверить регистрацию, вход после перезагрузки и перезапуска, две учётные записи и изоляцию их истории, запрет админ-API клиенту, редактирование базы знаний и ответ DeepSeek после изменений.

Адаптивный демонстрационный сайт с чатом, примерным каталогом услуг и приёмом демо-заявок. Адрес, телефон, сайт, цены и гарантии придуманы для прототипа.

## Запуск

Нужен Node.js 20 или новее. Установка пакетов не требуется.

1. Скопируйте `.env.example` в `.env` в корне проекта.
2. Для подключения DeepSeek вставьте значение ключа **только в локальный `.env`** после `DEEPSEEK_API_KEY=`. В чат, Git и frontend ключ не отправляйте. Переменная `LLM_API_KEY` больше не используется.
3. При необходимости измените `LLM_BASE_URL` и `LLM_MODEL`.
4. Запустите `npm start` и откройте `http://127.0.0.1:3000`.

Без ключа сайт работает в явно отмеченном **деморежиме**. Это набор примерных ответов для проверки интерфейса и пяти сценариев, не обращение к LLM. С ключом вопросы поступают в DeepSeek через серверный маршрут `/api/chat`. После добавления ключа проверен настоящий ответ DeepSeek на вопрос о стоимости лечения кариеса.

## Заявки

Напишите «Хочу записаться на приём». Агент по очереди запросит имя, телефон, услугу, удобные день и время, затем попросит проверить сведения. Демо-заявка хранится **только в памяти сервера** до перезапуска и никому не отправляется. Реальную запись нужно подтверждать через администратора клиники. Админ-панели в этой версии нет.

## Безопасность и ошибки

- Ключ читается только сервером из `DEEPSEEK_API_KEY`; во frontend не передаётся.
- `.env` исключён через `.gitignore`. Не добавляйте его в архив и репозиторий.
- Сервер проверяет входящие сообщения и ограничивает размер запроса.
- При ошибке провайдера, таймауте (12 секунд) или пустом ответе API возвращает понятное сообщение; интерфейс продолжает работать.
- Секреты и технический текст исключений не включаются в ответы API и логи.

## Структура

- `server.js` — сервер, маршрут чата и логика демо-заявок;
- `SYSTEM_PROMPT.md` — системный промт из четырёх блоков;
- `public/` — адаптивный интерфейс и иллюстрация зуба;
- `.env.example` — шаблон настроек.
