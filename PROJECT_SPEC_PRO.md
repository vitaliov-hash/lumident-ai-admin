# Техническое задание: LumiDent Pro

## Цель и текущее направление

Развивать LumiDent как цифрового администратора стоматологической клиники с открытым гостевым чатом для посетителей и отдельной защищённой панелью администратора. Клиенту не требуется регистрация, логин или пароль: он открывает `/user` и пользуется чатом. Администратор открывает `/admin` и входит под своей учётной записью с ролью `admin`.

Проект использует Node.js HTTP-сервер, статические HTML/CSS/vanilla JS страницы, DeepSeek через backend и PostgreSQL (Neon) для конфигурации Pro, ролей, сессий и базы знаний. Публичная версия на Render/GitHub отражает ранее развёрнутый код; новые локальные изменения не считать опубликованными до отдельного согласования и деплоя.

## 1. Клиентский доступ и администратор

- `/user` — открытый чат без регистрации, авторизации и запроса персональных данных для доступа.
- `/admin` — отдельная форма входа; регистрация на этой странице отсутствует.
- Сервер принимает парольный вход только с явной целью `admin` и только для пользователя с ролью `admin`.
- Публичный endpoint регистрации посетителей отключён. Назначение администратора выполняется доверенной процедурой, не через сайт.
- Роль и права проверяются сервером, а не только скрытием элементов интерфейса.
- Сессия администратора хранится в серверной PostgreSQL и передаётся в HttpOnly cookie с Secure на HTTPS; выход отзывает сессию.
- Смена пароля администратора требует действующий пароль, новый пароль длиной от 12 символов; при смене остальные сессии отзываются.
- Для гостевого чата история живёт только в текущей вкладке и не сохраняется в PostgreSQL. Постоянная история требует отдельного решения о клиентских аккаунтах и приватности; до этого не добавлять клиентский вход.

## 2. База знаний и панель

- Администратор может редактировать услуги, описания, цены «от» и часы работы без правки кода.
- Для услуг и часов хранятся варианты на русском и английском; публичные карточки и контекст AI получают актуальные данные из одного источника.
- Изменения сохраняются в PostgreSQL и защищены ролью `admin`.
- Если материалы или гарантии не содержатся в подтверждённых данных, AI должен честно обозначить отсутствие точной информации, не выдумывать ответ.
- При ошибках сохранения интерфейс показывает понятное сообщение.

## 3. AI и безопасность медицинских ответов

- DeepSeek вызывается только backend-сервером; ключ остаётся в защищённой переменной окружения и никогда не попадает в frontend или документацию.
- Ответ должен учитывать выбранный язык и актуальную базу знаний.
- Сохраняются правила `SYSTEM_PROMPT.md`: не ставить диагноз, не назначать лечение, направлять за очной консультацией и не советовать опасное самолечение.
- При неизвестных сведениях AI признаёт, что информации нет.
- Таймауты, пустые и ошибочные ответы API обрабатываются безопасно и не раскрывают технические секреты.
- Гостевой `/api/chat` ограничивает объём сообщений и частоту запросов и не сохраняет диалоги.
- Не обещать подтверждённую запись или доставку заявки сотруднику: интеграция календаря и передачи заявки не подключена.

## 4. Голос и языки

- Интерфейс и ответы чата доступны на русском и английском; язык выбирает посетитель, выбор запоминается в браузере.
- Услуги и часы имеют переведённые поля; если английское значение отсутствует, интерфейс использует русское как fallback.
- Голосовой ввод запускается только после явного нажатия пользователем кнопки микрофона. При отказе в разрешении или отсутствии браузерного API сохраняется ввод текстом.
- Озвучка ответа запускается только отдельным нажатием кнопки у сообщения. Используется встроенный синтез речи браузера; при отсутствии поддержки кнопка недоступна с пояснением.
- Не запрашивать доступ к микрофону без явного действия пользователя и не утверждать, что голосовые API одинаково доступны во всех браузерах.

## 5. Инфраструктура и данные

- В Pro-режиме используется постоянная PostgreSQL, включая миграции схемы и исходное заполнение базы знаний.
- Локальный fallback без `DATABASE_URL` даёт гостевой чат и справочную базу, но не полноценную авторизацию/админ-панель.
- `.env`, ключи, пароли, токены и строки подключения не коммитить и не записывать в `PROJECT_CONTEXT.md`.
- До использования реальных данных пациентов необходима отдельная правовая и эксплуатационная проверка.

## 6. Критерии проверки

1. Посетитель открывает `/user`, видит только клиентский чат и отправляет вопрос без аккаунта.
2. `/admin` показывает только вход администратора; регистрация посетителей в UI и API отключена.
3. Клиентская роль не может получить доступ к админ-панели или API знаний.
4. Гостевые диалоги не сохраняются между загрузками страницы и не привязаны к учётным записям.
5. Изменённые администратором услуги и часы после сохранения отражаются в публичном каталоге и AI-контексте.
6. Переключение RU/EN меняет подписи, каталог и язык запроса.
7. Голосовой ввод требует нажатия кнопки и имеет текстовый fallback; озвучка запускается вручную и корректно обозначает неподдерживаемый браузер.
8. Ошибка AI/БД не приводит к падению страницы и не раскрывает секреты.
9. Проверки Neon и DeepSeek выполняются только при настроенной локальной среде и без случайной публикации изменений.
