# Контекст проекта LumiDent

## Название проекта

LumiDent — AI-администратор стоматологической клиники.

## Цель приложения

Дать посетителям клиники справочную информацию об услугах и ценах через цифрового администратора, а администратору клиники — отдельный защищённый интерфейс для редактирования базы знаний. Посетителю не нужны регистрация или аккаунт.

## Текущая архитектура

- Backend: Node.js (`node:http`), статическая раздача frontend и JSON API.
- Основной локальный запуск: `server.js`; при наличии `DATABASE_URL` включается Pro backend из `pro-server.js`.
- Frontend: HTML, CSS и vanilla JavaScript в `public/`.
- `public/index.html` и `public/app.js` — клиентский гостевой чат и лендинг (`/user`).
- `public/pro.html` и `public/pro-app.js` — отдельная панель администратора (`/admin`).
- Pro-хранилище: PostgreSQL/Neon, запросы и миграции в `pro-db.js`; хранятся пользователи, роли, серверные сессии и изменяемая база знаний. Публичный гостевой чат историю в БД не сохраняет.
- Без `DATABASE_URL` запускается ограниченный локальный fallback: гостевой чат/справочник доступны, серверная админ-аутентификация и постоянная панель недоступны.
- `render.yaml` описывает конфигурацию развертывания; секреты задаются только окружением/защищёнными настройками хостинга.

## Основной функционал

- Адаптивный сайт клиники и гостевой чат без регистрации по `/user`.
- Отдельная форма входа для администратора по `/admin`; публичная регистрация посетителей отключена, API-вход принимает только цель `admin` и проверяет роль на сервере.
- Администратор редактирует услуги, описания, цены «от» и рабочие часы; изменения хранятся в PostgreSQL и используются публичным каталогом и контекстом AI.
- Каталог услуг и часы показываются на русском и английском.
- Гостевая история хранится только в памяти открытой страницы и исчезает при перезагрузке; аккаунты посетителей/история по аккаунтам отложены.
- Голосовой ввод активируется нажатием на кнопку микрофона через браузерный Web Speech API при поддержке браузера; текстовый ввод остаётся доступен.
- Озвучка ответа запускается вручную кнопкой у ответа через браузерный speech synthesis; если API отсутствует, контроль явно отключён.
- Ограничены размер сообщений и частота обращений; ошибки API показываются без технических секретов.
- Интеграции с календарём клиники и настоящей доставкой заявки нет; чат не должен обещать подтверждённую запись.

## AI-модель и API

- AI-провайдер: DeepSeek, совместимый endpoint `/chat/completions`.
- По умолчанию используются `LLM_BASE_URL` и `LLM_MODEL` из конфигурации; для прежнего прототипа значения по умолчанию — `https://api.deepseek.com` и `deepseek-chat`.
- Pro backend получает текущие услуги и часы из PostgreSQL и добавляет их к неизменяемым правилам системного промта.
- Секрет API хранится только в переменной окружения `DEEPSEEK_API_KEY`; ключи и значения окружения сюда не записываются.
- Таймаут запроса к провайдеру — 12 секунд. Ошибка/пустой ответ обрабатывается безопасно; в fallback-режиме используется справочный ответ.
- AI-ответ может быть запрошен на русском или английском в соответствии с выбранным языком интерфейса.

## Системный промт

- Главный файл правил: `SYSTEM_PROMPT.md`.
- Он определяет роль цифрового администратора, стиль общения, разрешённые факты о клинике, услуги/цены/гарантии, честное сообщение о пробелах знаний и медицинские ограничения.
- Нельзя ставить диагноз, назначать лечение, обещать доступность слота или реально отправленную заявку; опасное самолечение должно быть отклонено.
- В Pro актуальные изменяемые данные клиники подмешиваются с сервера из базы знаний; фиксированные факты из старого промта не должны подменять актуальные сведения базы.
- Текущие изменения не меняли `SYSTEM_PROMPT.md`.

## База знаний

- В Pro источник изменяемой информации — таблицы PostgreSQL `services` и `settings`; услуги включают русские и английские названия и описания, цену от; настройки содержат рабочие часы на обоих языках.
- Миграции и начальное заполнение базы описаны в `pro-db.js`.
- В локальном fallback сведения каталога встроены в `server.js`.
- Сведения о материалах и гарантиях доступны лишь в действующих утверждённых данных системного промта/справочника; отдельного редактора для них нет. Не выдумывать отсутствующую информацию.

## Требования к интерфейсу

- Доброжелательный, профессиональный, адаптивный стиль LumiDent для desktop и mobile.
- Раздельные маршруты: посетитель `/user` сразу попадает в чат без формы аккаунта; администратор `/admin` видит только свою форму входа и панель после проверки роли.
- RU/EN переключатель должен менять подписи интерфейса, каталог и язык запроса AI.
- Ответы пользователя и AI визуально разделяются; должны сохраняться состояния загрузки и понятной ошибки.
- Кнопку микрофона пользователь включает сам; отказ/отсутствие поддержки не блокирует обычный текстовый ввод.
- У каждого ответа есть ручная кнопка озвучки, отключаемая с пояснением, если браузер не поддерживает синтез речи.
- Интерфейс не раскрывает внутренние настройки, промт и секреты; текстовый ввод остаётся основным универсальным способом общения.

## Принятые решения

- Посетителю не требуется регистрироваться и входить: доступ к клиентскому чату открытый.
- Логин и пароль нужны только администратору; публичная регистрация отключена, роль администратора назначается отдельной защищённой процедурой.
- История гостевого чата не записывается постоянно. Возврат к истории после перезагрузки отложен вместе с клиентскими аккаунтами.
- Русский — основной язык; английский доступен как второй язык интерфейса и ответов.
- Голосовые возможности используют встроенные API браузера без отдельного внешнего провайдера; их поддержка зависит от браузера.
- Секреты не хранятся в коде и контекстных документах.
- Проект не считается системой медицинской диагностики или подтверждённой онлайн-записи.

## Текущая версия / состояние

- Версия пакета указана в `package.json`.
- Ранее LumiDent Pro был опубликован в публичном репозитории GitHub `vitaliov-hash/lumident-ai-admin` и развёрнут на Render; Neon PostgreSQL использовалась как production БД.
- Текущие изменения с гостевым входом по `/user`, отдельным админ-входом `/admin`, RU/EN и голосовыми функциями находятся только локально в рабочем дереве и не отправлялись на GitHub/Render.
- После текущих изменений гостевой endpoint не создаёт серверную историю. Production-среда продолжит вести себя по ранее опубликованному коду до согласованной публикации и деплоя.
- Реальная запись в систему расписания, доступность времени и доставка заявки сотруднику не интегрированы.
- Перед использованием реальных медицинских/персональных данных нужна отдельная проверка требований и процессов.

## Последние изменения

- Разведены гостевой маршрут `/user` и администраторский маршрут `/admin`; корневой маршрут Pro направляет посетителя в гостевой чат.
- Клиентский чат использует публичный `/api/chat`, не создаёт учётную запись и не сохраняет историю в PostgreSQL.
- Публичная регистрация отключена ответом 403; API парольного входа работает только для `targetRole: admin` и требует серверную роль `admin`.
- Добавлена английская локализация клиентского интерфейса, быстрых вопросов, услуг и часов; английские данные базы знаний доступны для админ-редактирования.
- Добавлены браузерный голосовой ввод по явному нажатию и ручная озвучка ответов. Для браузеров без speech synthesis отображается отключённая кнопка с пояснением.
- README, `PROJECT_SPEC_PRO.md` и `CODEX_PRO_PROMPT.md` приведены к гостевому доступу клиентов и отдельной авторизации администратора.
- Эти изменения локальные и не опубликованы.
- Автоматические тесты: `test/server.test.js` проверяет гостевые страницы, разделение UI, RU/EN каталог, пять сценариев ответов и ошибки API; `test/pro-integration.test.js` проверяет PostgreSQL-сессию администратора, запрет регистрации и client-login, чтение/редактирование базы знаний и отсутствие записи гостевых сообщений. `pnpm test` прошёл: 17 тестов, 0 ошибок, 0 пропусков. Тестовый процесс не вызывает DeepSeek.
- Для интеграционных тестов используется отдельная временная Neon-ветка `codex-test`, а её URL задаётся только в локальном игнорируемом `.env` как `LUMIDENT_TEST_DATABASE_URL`. Production-ветка в тестах не используется. Ветка Neon настроена на автоматическое истечение 27 сентября 2026 года.
- Интеграционный тест выявил и помог исправить ошибку парсинга сессионной cookie: сервер отбрасывал первый символ токена, из-за чего авторизованный администратор получал 401 при чтении панели. После исправления вход, сессия и admin API прошли тесты.
- Перед production-деплоем требуется заменить DeepSeek API key: прежний ключ оказался виден на присланном пользователем скриншоте. Само значение секрета в репозитории и контексте не хранить.
- GitHub `main` содержал независимые коммиты с реализацией LumiDent Pro и поддержкой Render Secret File `/etc/secrets/DATABASE_URL`; они объединены с локальными изменениями. Конфликтующие файлы оставлены в соответствии с проверенной локальной реализацией, изменения Render Secret File сохранены.
- После объединения `pnpm test` прошёл: 17 тестов, 0 ошибок, 0 пропусков; интеграционные тесты обращались только к временной Neon-ветке `codex-test`.
- Объединённая ветка `main` опубликована в публичном GitHub-репозитории. После push production Render отвечает `{"mode":"live","pro":true}`; `/user`, `/admin` и `/api/knowledge` вернули HTTP 200.
- В production проверен гостевой сценарий: вопрос «Какие часы работы клиники?» вернул живой ответ «Мы работаем ежедневно с 09:00 до 21:00». Неавторизованный запрос к `/api/admin/knowledge` получил HTTP 401. Вход администратора и редактирование базы вручную не проверены: пароль администратора не предоставлялся.
- Production Neon подключена к Render, но локальный `DATABASE_URL` не задан; тестовая ветка доступна локальным интеграционным тестам. Секреты не копируются в этот контекст.

## Следующие задачи

- После самостоятельного входа администратора вручную проверить чтение/редактирование базы знаний и клиентскую историю; не отправлять пароль через чат.
- До деплоя пользователь должен заменить DeepSeek API key в локальном `.env` и Render Environment; не запрашивать и не пересылать новое значение через чат.
- Отдельно пройти вручную тест на production с пользователем после деплоя; не запускать тестовый набор на production Neon.
- Проверить сохранение английских/русских услуг через админ-панель и актуальность каталога после сохранения.
- Проверить голосовой ввод вручную только после действия пользователя и разрешения микрофона; проверить озвучку в браузере с поддержкой speech synthesis.
- После проверки подготовить проверенный набор изменений, опубликовать на GitHub и развернуть на Render по запросу пользователя; затем проверить публичные `/user` и `/admin`.
- Если в дальнейшем понадобится история клиента, сначала согласовать отдельный клиентский аккаунт, согласие на хранение и срок удаления данных.
