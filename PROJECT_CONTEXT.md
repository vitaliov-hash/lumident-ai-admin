# Контекст проекта LumiDent

## Название проекта

LumiDent — AI-администратор стоматологии.

## Цель приложения

Адаптивный демонстрационный сайт стоматологической клиники с чатом цифрового администратора, справочной информацией об услугах и ценах, а также сценарием сбора демо-заявки на приём.

Адрес, телефон, сайт, цены и гарантии в прототипе являются вымышленными.

## Текущая архитектура

- Сервер: Node.js 20 или новее, встроенный модуль `node:http`; внешние npm-пакеты не требуются.
- Точка запуска: `server.js`, команда `npm start`.
- Сервер одновременно раздаёт статические файлы из `public/` и предоставляет API.
- API:
  - `GET /api/status` — возвращает режим `live` или `demo`.
  - `POST /api/chat` — принимает историю сообщений и отвечает в демо-режиме или через LLM.
- Клиент: HTML, CSS и vanilla JavaScript в `public/`.
- Конфигурация читается из локального `.env`; шаблон находится в `.env.example`.
- Системный промт загружается сервером из `SYSTEM_PROMPT.md`.
- Техническое задание сохранено в `PROJECT_SPEC.md`.
- Состояние заявок хранится только в памяти процесса сервера (`Map` и массив); постоянного хранилища нет.

## Основной функционал

- Лендинг LumiDent с разделами услуг, информации о клинике, чата и контактов.
- Чат с цифровым администратором.
- Быстрые кнопки для вопросов о кариесе, материалах и записи.
- Два режима работы:
  - live — запросы передаются в DeepSeek;
  - demo — используются встроенные примерные ответы без обращения к LLM.
- Сценарий демо-заявки: имя, услуга, желаемые день и время, необязательный телефон в конце диалога, подтверждение данных.
- Валидация сообщений, ограничение длины запроса и истории сообщений.
- Таймаут обращения к провайдеру — 12 секунд; предусмотрены понятные сообщения об ошибках.
- Адаптивная верстка для мобильных устройств.

## AI-модель и API

- Провайдер: DeepSeek.
- Базовый URL по умолчанию: `https://api.deepseek.com`.
- Модель по умолчанию: `deepseek-chat`.
- Endpoint: `/chat/completions` на указанном базовом URL.
- API-ключ читается только сервером из `DEEPSEEK_API_KEY` и не передаётся во frontend.
- Температура запроса: `0.3`.
- При отсутствии ключа приложение работает в демо-режиме.
- Переменная `LLM_API_KEY` больше не используется.

## Системный промт

Системный промт хранится в отдельном файле `SYSTEM_PROMPT.md`.

Он задаёт роль администратора LumiDent, достоверные данные клиники, услуги и цены, гарантии и материалы, правила русскоязычного профессионального общения, ограничения медицинских рекомендаций, обработку опасного самолечения и требования честно сообщать об отсутствии информации.

Полный текст технического задания сохранён в `PROJECT_SPEC.md`.

## База знаний

Отдельной базы данных или внешней базы знаний нет. Источник знаний — содержимое `SYSTEM_PROMPT.md` и встроенные демо-ответы в `server.js`.

Известные данные клиники: Москва, ул. Сиреневая, 18; телефон +7 (495) 123-45-67; сайт https://lumident.example; ежедневно 09:00–21:00. Услуги, цены, материалы и гарантии перечислены в системном промте.

## Требования к интерфейсу

- Русскоязычный, доброжелательный и профессиональный интерфейс.
- Адаптивность для desktop и mobile.
- Основные блоки: навигация, hero-секция, краткая информация о клинике, чат, популярные услуги, контакты и footer.
- В чате отображается текущий режим: «DeepSeek на связи» или «Справочник клиники».
- Ответы пользователя и администратора визуально разделены; предусмотрены состояния загрузки и ошибок.
- Интерфейс не должен раскрывать системный промт, технические настройки, ключи и токены.
- Информация в чате не заменяет очную консультацию врача.

## Принятые решения

- Реализация выполнена без framework и без обязательной установки зависимостей.
- Секреты хранятся только в локальном `.env`, который исключён из Git.
- При недоступности LLM сервер возвращает безопасное понятное сообщение без технических деталей исключения.
- Демо-заявка не считается подтверждённой записью и не отправляется сотруднику клиники.
- Для настоящей записи пользователь направляется к администратору по телефону.
- При отсутствии точной информации приложение не делает предположений и предлагает уточнить данные по телефону.

## Текущая версия / состояние

- Версия в `package.json`: `1.0.0`.
- Состояние: демонстрационный прототип.
- Node.js: `>=20`.
- Админ-панель: отсутствует.
- Постоянное хранение заявок и интеграция с реальной системой записи: отсутствуют.
- Настройка реального провайдера выполняется через `DEEPSEEK_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` и `PORT`.

## Последние изменения

- Версия LumiDent Pro опубликована в публичном GitHub-репозитории и развёрнута на Render. Neon PostgreSQL подключена к веб-сервису как Secret File `DATABASE_URL`, который сервер читает из `/etc/secrets/DATABASE_URL`. Сам секрет не записывается в код или контекст.
- Реализованы регистрация и вход клиента, серверные сессии, роли `client`/`admin`, отдельная панель администратора, редактирование списка услуг/описаний/цен/часов, публичные карточки из БД, сохранение диалогов и разграничение владельца на сервере.
- При первом старте выполняется создание таблиц и однократная загрузка исходного каталога. Неактивные 30 дней диалоги удаляются; пользователь также может удалить свой диалог.
- На публичном сервисе проверены HTTP 200 для главной страницы, ответ `/api/status` с `pro: true`, загрузка 9 услуг и часов из Neon, а также HTTP 401 для админ-маршрута без авторизации. Полные сценарии регистрации, изоляции двух аккаунтов, админ-редактирования и чата DeepSeek ещё не проходили.
- Для Pro текущие услуги и часы подаются в запрос DeepSeek из базы данных. Старые фиксированные сведения об услугах удаляются из системного контекста Pro при сборке запроса; файл `SYSTEM_PROMPT.md` не изменён.
- Диалоги Pro удаляются по запросу владельца и автоматически после 30 дней без активности. Реальная запись и доставка заявок не подключены; использовать реальные данные пациентов до правовой проверки не следует.

- Не указано в виде отдельного журнала изменений.
- По `README.md` и `TEST_REPORT.md` подтверждено подключение DeepSeek и проверка пяти сценариев.
- Проверенные сценарии включают стоимость лечения кариеса, материалы и гарантию, вопрос вне тематики, неподтверждённые сведения о парковке и опасное самолечение.
- Дата проверки, указанная в `TEST_REPORT.md`: 25 сентября 2026 года.
- Системный промт дополнен требованиями не использовать давление и манипуляции, повторять собранные данные перед передачей заявки и направлять за неотложной помощью при срочных состояниях.
- Прикреплённое техническое задание сохранено в `PROJECT_SPEC.md`.
- Добавлен безопасный fallback: при ошибке или таймауте DeepSeek чат отвечает встроенным справочником в режиме `demo`, чтобы интерфейс не оставался без ответа.
- Телефон в сценарии демо-заявки сделан необязательным: его можно пропустить, не блокируя оформление заявки.
- Вопрос о телефоне перенесён в конец сбора данных; любой ответ без распознанного номера трактуется как отказ от его указания.
- После указания даты и времени приложение подтверждает выбранные дату и время в заявке. Телефон предлагается только для связи в случае форс-мажорных изменений.
- Клиентские сообщения больше не называют заявку «демо»; подтверждение формулируется как принятие и отправка заявки.
- Из публичного интерфейса убраны формулировки «демо-заявка» и «демонстрационный прототип».
- Подтверждение заявки теперь показывает каждое поле с явной подписью, включая «Телефон: не указан».
- Краткие пожелания по дате и времени нормализуются: день без месяца относится к ближайшему будущему месяцу, а число часа трактуется как время с минутами `00`.
- Телефоны длиной от 9 цифр распознаются и сохраняются в заявке.
- Сервер подготовлен к размещению на Render: добавлены поддержка `HOST=0.0.0.0` и конфигурация `render.yaml`; секрет `DEEPSEEK_API_KEY` должен задаваться в Render Secrets.
- Проект размещён на Render; GitHub-репозиторий `vitaliov-hash/lumident-ai-admin` публичный. Адрес приложения: `https://lumident-ai-admin.onrender.com`.
- После деплоя проверены HTTP 200, режим `live` и ответ DeepSeek на вопрос о стоимости лечения кариеса.
- Статус подключения DeepSeek скрыт с лицевой стороны интерфейса.
- Нижние быстрые кнопки чата заменены на «Услуги», «Гарантия» и «Записаться»; для «Услуги» и «Гарантия» добавлены раскрывающиеся списки тематических вопросов.
